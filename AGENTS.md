# Agent Instructions

Canonical instructions for AI coding agents working in this repository.
Harness-specific aliases (`CLAUDE.md`, `.cursorrules`, `codex.md`, etc.) reference this file.

This file is the **index**. Detailed rules live in [`docs/agents/`](./docs/agents/).

## Vision and goal

**North star.** VLLNT UI is the mandatory UI layer for every vllnt product, in every environment: web, mobile, desktop and, next, spatial. It is the fastest way for humans and AI agents to build UIs. The vllnt brand is the default theme, and every component meets WCAG 2.2 AA.

**Where it is going.** VLLNT UI is also meant to be the foundation library for:

1. **3D, AR and spatial, and holographic interactive interfaces:** the same components and tokens rendered in 3D scenes and in space (for example WebGL, WebXR or visionOS), not a separate kit. Holographic interfaces means layered translucent panels in depth, data-dense HUD overlays, radial and orbital menus, gesture, gaze and voice input, and panels that are streamed live or generated by an agent.
2. **Dynamic, AI-generated UI:** interfaces that are streamed, composed at runtime by a model or a server, personalised for each user, and updated without a rebuild.
3. **Voice-first interfaces,** a core pillar next to generative UI: the UI follows the voice. That means conversational surfaces, a live transcript and listening states, push-to-talk and wake states, waveform and level indicators, spoken feedback that always has an accessible text equivalent, and voice-driven streamed UI through the AI SDK and json-render.
4. **First-class with the Vercel AI stack:** models can emit VLLNT UI trees through [json-render](https://github.com/vercel-labs/json-render) catalogs, and [AI SDK](https://ai-sdk.dev) generative UI (tool calls in `useChat` message parts, and RSC `streamUI`) renders VLLNT UI components.

**Default look: full glassmorphism.** Glass is the default theme on the web, page chrome and ui.vllnt.com included, not an optional theme. Black and white, Inter and JetBrains Mono stay the base tokens underneath. Text-bearing glass keeps WCAG 2.2 AA contrast through two tints, default and dense, checked in `packages/ui/src/lib/glass-contrast.test.ts`. CSS turns glass solid under `prefers-reduced-transparency`, `prefers-contrast: more`, `forced-colors` and without `backdrop-filter`; `html[data-glass="off"]` and the `material="solid"` prop do it by hand, and every glass component takes `material`. Native platforms without blur are not covered yet. Rules, tokens and the blur budget are in [DESIGN.md](./DESIGN.md), Glass material; tracked in [#684](https://github.com/vllnt/ui/issues/684).

**Platforms.** VLLNT UI is meant for every kind of UI. Status on `main` (21 Nov 2026); never describe a target as further along than this table:

| Target | Status | What exists today |

Each canary pair is installed in a clean Expo app and exported for iOS and Android before it counts ([`packages/ui-native/README.md`](./packages/ui-native/README.md)). |

| AR and spatial: visionOS, WebXR | **RFC** | Spatial foundations are a draft RFC ([#631](https://github.com/vllnt/ui/issues/631), [PR #632](https://github.com/vllnt/ui/pull/632)). No renderer. |

| Voice-first UI | **Roadmap** | No voice component ships: no microphone capture, transcript, listening state, waveform or speech output. `AIStreamingText` announces streamed text through a live region, which can carry the text equivalent of spoken output. **Architecture rule: one platform-neutral core, one renderer per platform.** This is what lets the same components reach new targets.

- The core is platform-neutral: tokens, component contracts (option and prop names), platform rules and, later, the props schemas behind the descriptors. It lives in [`packages/design`](./packages/design) (`tokens.json`, `component-contracts.json`, the source) and [`packages/ui-core`](./packages/ui-core) (the generated, importable form). `@vllnt/ui-core` has no runtime dependencies and imports no renderer, DOM or React Native API. Keep it that way.
- Each platform is a renderer on top of the core: `@vllnt/ui` (React DOM) and `@vllnt/ui-native` (React Native) today; desktop, native macOS, visionOS and WebXR renderers later.
- Dependencies point one way: a renderer depends on the core, never the reverse, and no renderer imports another. A decision two platforms share goes into the core first.
- Today, honestly: `@vllnt/ui-native` reads tokens and contracts from `@vllnt/ui-core`; `@vllnt/ui` gets the same tokens as CSS generated from `packages/design` and does not import `@vllnt/ui-core`. Descriptors (`/r/*.json`) are built by the registry app; moving their platform-neutral part (props schemas) into the core is roadmap ([#672](https://github.com/vllnt/ui/issues/672)).

Read the long form at [`/vision`](https://ui.vllnt.com/vision) (source: [`apps/registry/content/pages/vision/`](./apps/registry/content/pages/vision/)).

**Design rules that follow.** Apply them to every change. "Today" means it is on `main`; "Roadmap" means it is planned and not shipped. Never describe a roadmap item as available.

| Rule | Today | Roadmap |
|------|-------|---------|
| **Describable components.** Give new props plain, serialisable values (strings, numbers, booleans, arrays, plain objects); pass React nodes only through `children` or named slots, and behaviour through event handlers. Every component has a machine-readable descriptor, so an agent or a server can pick and compose it. | `/r/<name>.json` for every component, `/r/registry.json`, `llms.txt`, `llms-full.txt`, the MCP server at `/mcp` (`search_components`, `get_component`, `list_categories`). Every descriptor carries its version and stability; prop definitions and usage examples exist for only a few components so far ([`apps/registry/registry.json`](./apps/registry/registry.json), schema in [`apps/registry/lib/registry.ts`](./apps/registry/lib/registry.ts)). | A complete JSON schema of the props of every component, so a model can produce a valid UI tree and a renderer can check it before rendering. |
| **Tokens and themes are data.** No hard-coded colours, sizes or fonts in components: use the tokens. A theme is a data layer that can be switched at runtime. | [`packages/design/tokens.json`](./packages/design/tokens.json) generates the CSS variables, the product themes (`data-theme`, [`themes/products.css`](./packages/ui/themes/products.css)), the native tokens and Penpot. | Themes resolved per user at runtime (for example a generated theme for one person), within the accessible token ranges. |
| **Streaming-safe rendering.** Components render a stable layout before their data arrives, have loading, empty and error states, and don't shift layout when content streams in. | `Skeleton`, `AIStreamingText`, `Reasoning`, `ThinkingBlock` and `AgentActivity`; React Server Components are supported (client components are marked `"use client"`). | A documented contract for partial props, so any component can render from incomplete, streamed data. |
| **Safe auto-updates.** A consumer on a pinned version can take a new one without breaking. | Semver, a canary on every merge to `main`, stable releases only from reviewed `v*` tags, `latest` never moves backwards, upgrade notes in [`packages/ui/CHANGELOG.md`](./packages/ui/CHANGELOG.md), rollback by `npm deprecate` ([`docs/RELEASING.md`](./docs/RELEASING.md)). | Codemods for breaking changes and a written deprecation window, so updates can be applied automatically. |
| **Accessibility holds for generated UI.** WCAG 2.2 AA applies to a composed screen, not only to each component. Generated UI must keep labels, focus order, contrast and target sizes. | Storybook runs axe (WCAG 2.0 to 2.2, A and AA) on every story, in light and dark, and fails on any violation. Accessible names have English defaults. | Checks that run on a generated UI tree before it is shown. |
| **Glass by default, solid when needed.** New surfaces use the glass tokens, never local blur values. Text on glass meets WCAG 2.2 AA against a worst-case backdrop. Every glass component has a solid variant, and the solid fallback applies under `prefers-reduced-transparency`, `prefers-contrast`, `forced-colors`, without `backdrop-filter` support, on low-power devices and on native without blur. | On the web: glass tokens, glass as the default for every chrome-bearing component, a `material` prop on each, CSS fallbacks for the browser settings above and `data-glass="off"`, contrast tests and a static `backdrop-filter` budget ([#684](https://github.com/vllnt/ui/issues/684)). Native has no glass. | Glass on native, a runtime count of blurred layers, and the scrolled header tint for the site shells. |
| **Voice has a text and a keyboard path.** Every spoken output has visible, selectable text; every voice action can also be done by keyboard and pointer; listening is announced and never shown by colour or motion alone; the UI shows when the microphone is live and stops it in one step. | No voice components yet. Live regions (`AIStreamingText`) and the axe gate already apply to text output. | The voice-first component set and its accessibility tests ([#683](https://github.com/vllnt/ui/issues/683)). |
| **Works with json-render and the AI SDK.** Write each component so a json-render catalog entry (a zod `props` schema plus a `description`) and an AI SDK tool `inputSchema` can describe it, and so it renders from those props alone. Give every async view a loading state (`input-streaming` / `input-available`) and an error state (`output-error`). Check APIs against the published packages, not memory, and only propose dependency versions at least 7 days old. | No adapter ships. The AI family components (`AIStreamingText`, `Reasoning`, `AIToolCallDisplay`, `AISourceCitation`, `ApprovalRequest` and others) are plain React, so you can render AI SDK message parts with them by hand. zod 4 is already in the repo, matching json-render's peer range. | A json-render catalog and registry (like `@json-render/shadcn`), zod prop schemas per component that also fill `/r/<name>.json` `props`, and AI SDK helpers that map `tool-${name}` parts to components: [#672](https://github.com/vllnt/ui/issues/672). |
| **Platform-agnostic core.** Shared decisions (tokens, component contracts, platform rules) live in [`packages/ui-core`](./packages/ui-core) and [`packages/design`](./packages/design), never inside one renderer. | Web (`@vllnt/ui`) and React Native (`@vllnt/ui-native`) are generated from the same tokens and contracts in `packages/design`; native reads them through `@vllnt/ui-core`. Every interactive native component uses one affordance primitive (`InteractivePressable`: pressed, hovered, focused and disabled states, plus a touch-target floor). | Spatial renderers. The [spatial-ready foundations RFC](https://github.com/vllnt/ui/pull/632) (issue [#631](https://github.com/vllnt/ui/issues/631), draft, targets 0.5.0) proposes depth tokens, one affordance contract for pointer, touch and gaze, input-agnostic target sizes (24 px pointer, 44 pt touch, 60 pt spatial) and motion tokens. |

When a change would break one of these rules, say so in the PR body and link the issue that accepts the trade-off.

## React health (react-doctor)

[react-doctor](https://github.com/millionco/react-doctor) scans React-specific
correctness, a11y, and dead-code health. Three surfaces, one shared gate
(**errors block, warnings are advisory**):

| Surface | Trigger | Gate |
|---------|---------|------|
| CI ([`.github/workflows/react-doctor.yml`](./.github/workflows/react-doctor.yml)) | PR (diff) + push to main (full report) | `--fail-on error` |
| Pre-commit ([`.githooks/pre-commit`](./.githooks/pre-commit)) | `git commit` with staged `.ts/.tsx` | `--fail-on error` on staged files |
| Local | `pnpm doctor*` scripts | per script |

The pre-commit hook is enabled automatically: the root `package.json` `prepare`
script points `core.hooksPath` at `.githooks/` on `pnpm install`. Bypass once
with `git commit --no-verify`.

### Config — [`doctor.config.json`](./doctor.config.json)

- `ignore.files` skips generated/build output so the score reflects hand-written
  source: `registry/default/**` (untracked shims generated from
  `packages/ui/src` by `inline-component-source.ts`), `storybook-static`, `dist`, `.next`, Pagefind
  and shadcn registry output, and `*.visual.tsx` Playwright CT fixtures (test
  entry files the import graph can't see).
- Two rules are `off` because they conflict with deliberate library patterns:
  `no-multi-comp` (compound components such as `Alert`/`AlertTitle` co-located
  by design) and `only-export-components` (shadcn `cva` variants/types
  co-exported with the component).

## Internationalization (registry app)

The registry site (`apps/registry`) is multilingual via
[next-intl](https://next-intl.dev). Locales live in one place —
[`i18n/locales.ts`](./apps/registry/i18n/locales.ts) — and everything derives
from `routing.locales`. The default locale (`en`) is unprefixed; others are path
-prefixed (`/fr/...`) under the `as-needed` strategy.

**Content tracks - pick by shape, never mix them for the same string:**

| Track | For | Where |
|-------|-----|-------|
| next-intl messages | UI chrome: nav, buttons, labels, form fields, breadcrumbs, stat labels, structured-page prose | [`messages/<locale>.json`](./apps/registry/messages), consumed with `useTranslations` (client) / `getTranslations` (server) |
| MDX per locale | Long-form document pages: docs, vision | `content/pages/<slug>/<locale>.mdx`, loaded by `lib/content.ts` |
| Articles | Indexable how-tos, comparisons, roadmap notes (own frontmatter, feeds, `draft` flag) | `content/articles/<slug>/<locale>.mdx`, loaded by `lib/articles.ts`; see the Articles section of [`apps/registry/README.md`](./apps/registry/README.md) |

**Rules for agents touching the registry UI:**

- Never hardcode a user-facing string in JSX. Add a key to `messages/en.json` +
  every other locale, and read it via `t(...)`.
- Internal links use `import { Link } from "@/i18n/routing"` (auto-prefixes the
  locale). Keep plain `<a>` only for external URLs and non-localized assets
  (`/r/*`, `/llms.txt`, `/rss.xml`, `/mcp`).
- French house style is **diacritic-stripped** (no accented characters) — match
  the existing catalog and MDX.

**Drift gate — `pnpm -F @vllnt/ui-registry i18n:check`**
([`scripts/check-i18n.ts`](./apps/registry/scripts/check-i18n.ts)) fails when the
locales drift apart: message-key parity, MDX coverage (every content page in
every locale), and dead/undefined message namespaces. E2E proof lives in
[`e2e/i18n.spec.ts`](./apps/registry/e2e/i18n.spec.ts).

**Add a language** (e.g. `es`): (1) add it to `locales` in `i18n/locales.ts`;
(2) copy `messages/en.json` to `messages/es.json` and translate the values;
(3) add `content/pages/<slug>/es.mdx` for every content page; (4) run
`i18n:check` until green.

## Quick reference

The most-violated rules in PR review history:

0. **Design rules are mandatory for UI work.** Any UI suggestion or component/site change must follow [`DESIGN.md`](./DESIGN.md) (live at `https://ui.vllnt.com/DESIGN.md`) and the machine-readable tokens in [`packages/design/tokens.json`](./packages/design/tokens.json). List any intentional deviation in the PR body.
1. **Workspace gates green at HEAD** ([R6](./docs/agents/RULES.md#r6--workspace-gates-green-at-head)). Touched-file passes alone are not ship-OK. Run `pnpm -F @vllnt/ui lint && pnpm check:atomic && pnpm -F @vllnt/ui exec tsc --noEmit --project tsconfig.build.json && pnpm build && pnpm test:once` — all must be green.
2. **PR body matches HEAD** ([R3](./docs/agents/RULES.md#r3--pr-body-matches-head)). After every push, rewrite the body to match the current head. Stale claims block ship.
3. **Linked issue required** ([R5](./docs/agents/RULES.md#r5--linked-issue-required)). Every PR must reference a GitHub issue. Accepted keywords: `close` / `closes` / `closed`, `fix` / `fixes` / `fixed`, `resolve` / `resolves` / `resolved`, or repo phrases `Part of` / `Related to` — all case-insensitive, optional colon — followed by `#123` or `owner/repo#123`.

## Out of scope for agents

- Don't modify `LICENSE`, `CODE_OF_CONDUCT.md`, or `SECURITY.md` without explicit human authorization.
- Don't add new dependencies without explaining the tradeoff (bundle size, maintenance, security surface).
- Don't publish, push to `main`, or merge PRs without explicit authorization.
- Don't hand-edit generated files (`apps/registry/lib/component-metadata.json`, `dist/`). Regenerate via the documented script.
